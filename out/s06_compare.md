# Step 6 — Pre vs current vs 2026: what the review changed

Generated by `s06_compare.py` (`make s06`); do not edit by hand. `out/dataset_pre.csv` and `out/dataset_post.csv` are written by `s04_methodology.py`.

Three views of the same labels. *Pre* = the first value, from step 4's keyword rules or the corpus attack-vector label, 'unstated' where neither gave one (`out/dataset_pre.csv`). *Current* = the reviewed value reported in step 4 (`out/dataset_post.csv`). *2026* = the current value for the 1,416 records dated 2026 (`out/dataset_post_2026.csv`; the corpus year is often the ingestion year, Table 1.5). ## Why labels changed: worked examples

Each example illustrates one of the common moves; the count is how many labels made the same move (all years / 2026). The reasons are the reviewers' own notes.

**ON-AI**

1. *Entry point: stolen or leaked credential → exploit of a conventional software vulnerability* (26 / 24 labels). **INC-15866** (cve/ghsa, 2026), *AWS HealthLake MCP Server SSRF via Pagination URL*  
   Pre: the keyword rule matched “credential”, giving 'stolen or leaked credential'. Current: 'exploit of a conventional software vulnerability'. Why: SSRF via crafted next_token is the entry; credential theft is the impact.

2. *Entry point: direct prompt by the user → indirect carrier (web/email/doc/tool output)* (38 / 17 labels). **INC-00898** (cve/ghsa, 2026), *Discourse — Prompt Injection (CVE-2026-27740)*  
   Pre: the keyword rule matched “Prompt Injection”, giving 'direct prompt by the user'. Current: 'indirect carrier (web/email/doc/tool output)'. Why: AI triage reads flagged forum post carrying injection; attacker does not prompt directly.

3. *Entry point: indirect carrier (web/email/doc/tool output) → exploit of a conventional software vulnerability* (49 / 35 labels). **INC-02870** (cve/ghsa, 2026), *RMCP — Vulnerability (CVE-2026-42559)*  
   Pre: the keyword rule matched “website”, giving 'indirect carrier (web/email/doc/tool output)'. Current: 'exploit of a conventional software vulnerability'. Why: Host header not validated; DNS rebinding is a conventional bug.

4. *Target: consumer chatbot / hosted LLM app → a model itself (vision, speech or text model attacked directly)* (102 / 56 labels). **INC-03607** (research/other, 2024), *Best-of-N Jailbreaking*  
   Pre: the keyword rule matched “GPT-4”, giving 'consumer chatbot / hosted LLM app'. Current: 'a model itself (vision, speech or text model attacked directly)'. Why: Jailbreak research on GPT-4o, Claude 3.5 Sonnet, Gemini, Llama.


**WITH-AI**

5. *AI medium: synthetic audio/voice → synthetic video* (73 / 6 labels). **INC-04816** (harm-db, 2023), *Purported Deepfake Video Falsely Depicts Biden Announcing National Draft for Ukraine*  
   Pre: the keyword rule matched “Synthetic Audio”, giving 'synthetic audio/voice'. Current: 'synthetic video'. Why: Title says deepfake video.

6. *AI medium: deepfake, medium not stated → synthetic video* (54 / 23 labels). **INC-00512** (harm-db, 2026), *AI-Generated Videos Used in Religious Charity Scam in Taiwan*  
   Pre: no keyword matched; the corpus label 'deepfake' gave 'deepfake, medium not stated'. Current: 'synthetic video'. Why: Title says AI-generated videos.

7. *AI medium: deepfake, medium not stated → no attacker: operator harm or model failure (misplaced record)* (88 / 47 labels). **INC-00675** (harm-db, 2026), *Baltimore Sues Elon Musk's xAI Over Grok Deepfake Harms*  
   Pre: no keyword matched; the corpus label 'deepfake' gave 'deepfake, medium not stated'. Current: 'no attacker: operator harm or model failure (misplaced record)'. Why: Title is a city lawsuit against xAI; lawsuit story, no adversary described.

8. *Objective: defamation / impersonation of a person → intrusion / cyber operation* (38 / 15 labels). **INC-09141** (cve/ghsa, 2026), *MinIO has JWT Algorithm Confusion in OIDC Authentication*  
   Pre: the keyword rule matched “Impersonat”, giving 'defamation / impersonation of a person'. Current: 'intrusion / cyber operation'. Why: Forged tokens to obtain S3 credentials; intrusion.

## What the comparison says

- The review replaced 38.4% of the ON-AI first values (2026: 37.5%) and 30.3% of the WITH-AI ones (2026: 30.2%): in both populations the 2026 records needed as much correction as all years.
- ON-AI: 9.6% of records turned out to describe no attacker. Entry point: exploit of a conventional software vulnerability, a value the first rules never give, now holds 26.4%; direct prompt by the user fell 9.4 points. Target: a model itself (vision, speech or text model attacked directly), a value the first rules never give, now holds 11.4%; consumer chatbot / hosted LLM app fell 9.0 points (Table 6.1).
- WITH-AI: 11.8% describe no attacker and 5.5% are conventional-exploit records misplaced in WITH-AI. AI medium: synthetic video rose 9.4 points; deepfake, medium not stated fell 15.8 points. Objective: intrusion / cyber operation rose 8.6 points (4.6 points of it from records the review could not place as attacks); financial fraud / extortion fell 1.1 points (Table 6.2).
- 2026 vs all years, current values, largest gap per dimension: ON-AI exploit of a conventional software vulnerability 34.8% vs 26.4%; agent / copilot / coding assistant / MCP 57.5% vs 45.2%; WITH-AI synthetic audio/voice 5.5% vs 14.6%; political / influence 12.4% vs 19.0%. 2026 ON-AI records lean toward the cve/ghsa channel (61% against 45% for all years), which holds most conventional exploits and agent targets (Tables 4.1–4.2). None of these gaps is a trend: the record year is often the ingestion year.
- The examples show three things a keyword cannot tell: whether a word names the attack or only its impact or context ('credential', 'prompt injection', 'impersonate' in a CVE); whether a product or entity name is the thing attacked or produced ('GPT-4'; the AI Incident Database's 'Synthetic Audio' tag); and whether a corpus label ('deepfake') fits a story that states its medium or describes no attack.
