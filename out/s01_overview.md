# Step 1 — Overview

Inputs: genai-incidents 2.12.0, full JSON sha256 83295199da35…. Generated by `s01_overview.py` (`make s01`); do not edit by hand.

How to read the tables: n is the denominator of the % column. It counts records unless the description says otherwise. % is rounded to one decimal. Where a table lists only the most frequent values, the remaining values are pooled in a last row, so each % column covers all of n. Where a column still does not sum to 100.0, a line under the table says why.

## C. What incident-rank-validation shows about this data

Read from the committed artifacts of incident-rank-validation's 2026 OWASP LLM cycle; the engine is not run. These numbers are used to exclude out-of-scope rows, seed samples and set expectations, never for a cross-entry prevalence claim.

- Snapshot: 7,714 records (May 2026), of which 6,639 carry a classifier label. 6,399 of the labelled ids still resolve to a current record and 240 do not. The corpus has merged duplicates since the snapshot, so the resolving ids land on **6,207** distinct current records; everything below is counted on those.
- Label source: stage-1 rules 548, stage-2 LLM 5,659.
- Gold set: 1,200 hand-adjudicated rows; adjudicator overrode the model on 553; out of scope (no entry applies): 444.
- Gold rows after the join: 1,117 of 1,200 are attached to a current record (55 sit on ids that no longer resolve, 28 lose their label where merged duplicates collapse onto one record), including 441 of the 444 out-of-scope rows.
- Headline: weighted κ vote-vs-data = 0.203; frame-blind entries: LLM04, LLM08, LLM10.
